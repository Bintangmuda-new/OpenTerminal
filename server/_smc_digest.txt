### FINDINGS
- Swing point (ICT canonical): 3-candle fractal, k=1. Swing high = C2.high > C1.high AND C2.high > C3.high. Swing low mirrored. Only confirmed when C3 CLOSES (no repaint on live candle). Same candle can be both SH and SL (wide news candle).
  src: https://liquidityscan.io/blog/what-is-a-swing-high-and-swing-low-in-ict-the-3-candle-rule ; https://www.thedtterminal.com/academy/ict-market-structure ; https://innercircletrader.net/tutorials/ict-mar
- Swing point (alternate algorithm): Bill Williams classic fractal = 5-bar window (2 lower highs/lows each side). ICT tightens to 3 bars: faster, noisier. Libraries expose swing_length: incrypto default 5 (bars each side), Hadal default k=1 (3-bar), smc-python default swing_length=50 (large, meant for HTF structure).
  src: https://liquidityscan.io/blog/... ; https://hadalinstruments.com/ict/market-structure-indicator/ ; https://terminal.incrypto.ru/en/indicators/smc/market-structure ; https://github.com/joshyattridge/sm
- Swing tiers (recursive fractal): STH/STL = raw 3-candle pivot. ITH/ITL = STH with lower STH on both sides (apply same rule to swing points). LTH/LTL = ITH flanked by lower ITHs. Same comparison at 3 zoom levels.
  src: https://liquidityscan.io/blog/... ; https://hadalinstruments.com/ict/market-structure-indicator/
- BOS (Break of Structure): Close beyond the most recent swing point IN the trend direction. Uptrend = close above last swing high. Confirms continuation. Default = BODY CLOSE, not wick (Hadal, Velotrade, DT Academy all default close; smc-python close_break=True).
  src: https://velotrade.com/blog/break-of-structure ; https://www.thedtterminal.com/academy/ict-market-structure ; https://hadalinstruments.com/ict/market-structure-indicator/
- CHoCH (Change of Character): First close AGAINST the trend. Uptrend = close below the last HIGHER LOW (the swing that launched the latest high). SMC-community term; ICT calls the stricter version MSS. Warning only, not confirmation.
  src: https://velotrade.com/blog/break-of-structure ; https://oyamori.com/learning/ict-vs-smc-terminology/ ; https://www.thedtterminal.com/academy/ict-market-structure
- MSS vs CHoCH vs BOS: BOS = continuation break (many per trend). CHoCH = first counter-trend break, softer warning. MSS (ICT) = counter-trend break WITH displacement (+FVG), the confirmed reversal. Order: CHoCH then BOS, never reverse. ICT-based models require body close + displacement for MSS.
  src: https://innercircletrader.net/tutorials/ict-market-structure-shift/ ; https://www.thedtterminal.com/academy/ict-market-structure
- Order Block (core): LAST OPPOSING CANDLE before a displacement move. Bullish OB = last DOWN-closing candle before bullish displacement. Bearish OB = last UP-closing candle before bearish displacement. The candle alone is not enough — needs displacement away (structure break and/or FVG) to qualify. Work BACKWARD from the displacement, not forward from a promising candle.
  src: https://www.luxalgo.com/library/concept/bullish-bearish-order-block/ ; https://oyamori.com/learning/ict-vs-smc-terminology/ ; https://zayecapitalmarkets.com/order-block-in-trading/
- Order Block bounds (the contested part): Three conventions: (a) BODY only (open-to-close) — tighter, more precise, most common in SMC education; (b) FULL RANGE wick-to-wick — widest honest zone; (c) HYBRID — plan entry off body, keep wick extreme as invalidation. 50% 'mean threshold' line marks the block's midpoint; prefer entries in the deeper half. When several opposing candles stack, either take the one nearest the move origin or merge the cluster into one zone.
  src: https://www.luxalgo.com/library/concept/order-block-anatomy-and-refinement/ ; https://zayecapitalmarkets.com/order-block-in-trading/
- Order Block lifecycle: MITIGATED = price returned and traded into it (used once, downgraded after). INVALIDATED = price closes through the far side → many re-label it a BREAKER block (failed OB, polarity flip) rather than delete. smc-python default close_mitigation=False (mitigate on high/low touch, not close).
  src: https://www.luxalgo.com/library/concept/order-block-anatomy-and-refinement/ ; https://oyamori.com/learning/ict-vs-smc-terminology/ ; https://github.com/joshyattridge/smart-money-concepts
- Displacement (OB/FVG qualifier): Strong one-directional move: body 1.5x-3x recent average, wicks <20% of body (equivalently body >=80% of candle range), ideally 2-4 consecutive impulsive candles (3 = gold standard), leaves an FVG, and breaks a swing. Without displacement the preceding candle is just noise, no OB exists.
  src: https://www.quantum-algo.com/blog/guides/displacement-trading-complete-guide/ ; https://traderthabza.com/writing/ict-displacement ; https://acy.com/en/market-news/education/anatomy-of-a-valid-order-bl
- Fair Value Gap (FVG): 3-candle imbalance. Bullish FVG = low(C3) > high(C1). Bearish FVG = high(C3) < low(C1). Zone = sliver between C1 wick and C3 wick (NOT the middle candle's body). C2 = the thrust candle. If C1 and C3 overlap by any amount, no FVG regardless of C2 size. Consequent Encroachment (CE) = exact midpoint = (top+bottom)/2. Price returns to rebalance.
  src: https://steady-turtle.com/knowledge/mastering-fair-value-gaps/understanding-fair-value-gaps ; https://www.novacalculator.com/forex-trading/ict-smc-tools/fair-value-gap-calculator/ ; https://innercircl
- FVG variants: BISI = bullish FVG (Buyside Imbalance Sellside Inefficiency). SIBI = bearish FVG. Implied FVG (IFVG) = no true FVG; use CE of C1 and C3 wicks when both outer candles have long wicks. ICT: FVG fills on a lower TF = liquidity void.
  src: https://time-price-research-astrofin.blogspot.com/2024/04/ict-fair-value-gap-darya-filipenka.html ; https://www.novacalculator.com/forex-trading/ict-smc-tools/fair-value-gap-calculator/
- Liquidity sweep / stop hunt: Trade THROUGH a prior swing extreme (or equal highs/lows cluster) then CLOSE back inside — reclaim. Four phases: approach, spike, reclaim, reverse. Reclaim = sweep; acceptance/hold beyond = genuine breakout (BOS). Without reclaim, identical bar is just a breakout in progress. BSL = buy-side liquidity above highs; SSL = sell-side below lows.
  src: https://artoftrading.com/concepts/liquidity-sweeps/ ; https://hadalinstruments.com/glossary/liquidity-sweep/ ; https://liquidityscan.io/blog/liquidity-sweep-vs-liquidity-grab-is-there-a-difference
- Equal Highs/Lows (EQH/EQL): Two or more swing points at nearly the same price = a bigger, more obvious stop pool. Equality is a TOLERANCE parameter, not a fact. smc-python liquidity() default range_percent = 0.01 (1% of range). Cleaner/more respected the level, the bigger the assumed pool.
  src: https://oyamori.com/learning/courses/smc-ict-fundamentals/lesson-2-liquidity-and-stop-hunts/ ; https://artoftrading.com/concepts/liquidity-sweeps/ ; https://github.com/joshyattridge/smart-money-concep
- Premium/Discount: Take the dealing range (leg between a meaningful swing low and swing high). Split at 50% = equilibrium. Above 50% = PREMIUM (short zone), below = DISCOUNT (long zone). Range anchors must themselves have swept liquidity (low took SSL, high took BSL) or every derived zone is noise. Re-anchor when price closes beyond either extreme.
  src: https://www.luxalgo.com/library/concept/premium-and-discount/ ; https://ictflow.com/blog/ict-premium-discount-zones ; https://liquidityscan.io/blog/how-to-draw-a-dealing-range-in-ict-correctly
- OTE (Optimal Trade Entry): 62%-79% retracement band inside the favored half. 62% = zone start, 70.5% = sweet spot, 79% = deepest acceptable. Shallower than 62% = not enough discount; deeper than 79% = leg probably failing. Every OTE long is a discount buy; most of discount is not OTE.
  src: https://ictflow.com/blog/ict-premium-discount-zones ; https://www.ictkillzone.com/tools-ote-calculator ; https://www.tradingview.com/script/q6O0kR6a-ICT-Dealing-Range-EmpArchitect/
- Multi-timeframe bias: Top-down, HTF governs. Weekly/Monthly = macro trend + major pools. Daily = daily bias (long or short only today). 4H = draw on liquidity (DOL = target). 1H = model confirmation. 15M/5M = entry zone (OB/FVG). HTF and LTF MUST agree; conflicting LTF setup against HTF bias = stand aside (potential Judas swing). Only exception: HTF itself transitioning via confirmed CHoCH.
  src: https://www.theinnercircletraders.com/ict-top-down-analysis/ ; https://smartmoneyict.com/ict-timeframes-position-swing-scalping/ ; https://tradingfinder.com/education/forex/ict-time-frame/
- Killzones (session times, NY local): Asia 20:00-22:00, London 02:00-05:00, NY AM 07:00-10:00 (forex; 08:30-11:00 for index futures), London Close 10:00-12:00, NY Lunch 12:00-13:30, NY PM 13:30-16:00. Set chart to America/New_York so EST/EDT auto-adjusts.
  src: https://icttraders.net/ict-killzones/ ; https://www.quantum-algo.com/blog/guides/ict-trading-strategy-complete-guide/
- Entry rule practitioners actually use: Standard SMC reversal sequence: (1) HTF bias + meaningful HTF zone; (2) LTF liquidity sweep of obvious high/low (wick beyond, close back); (3) CHoCH/MSS with displacing candle; (4) LIMIT entry at the ORDER BLOCK that launched the CHoCH move, ideally overlapping the FVG from the same move (or enter on FVG fill); (5) stop below the OB / below the sweep low; (6) target next liquidity pool above (equal highs), partials at 2R.
  src: https://replaytrader.io/strategies/smart-money-concepts-strategy/ ; https://huntersalgo.com/guides/ict-liquidity-sweep-explained ; https://www.theinnercircletraders.com/ict-top-down-analysis/
- Two competing schools (state both): ICT (Huddleston) = original, strict: requires displacement + FVG for MSS, names Rejection/Propulsion blocks, PD Array. SMC (community repackage ~2019) = lighter rules, BOS/CHoCH headline, OB is a single-candle refinement of traditional supply/demand. Every OB sits inside a supply/demand zone; not every S/D zone is an OB. Neither OB-bounds nor equality-tolerance is standardized — treat all as filters to TEST, not laws.
  src: https://oyamori.com/learning/ict-vs-smc-terminology/ ; https://www.luxalgo.com/library/concept/order-block-anatomy-and-refinement/
